# 流式传输实体事件

**端点**: `POST /api/v1/entities/stream`

**cURL**

```bash
curl -X POST https://example.developer.anduril.com/api/v1/entities/stream \
     -H "Authorization: Bearer <token>" \
     -H "Content-Type: application/json" \
     -d '{}'
```

建立 server-sent events (SSE) 连接，实时流式传输实体数据。这是遵循 SSE 协议、内容类型为 text/event-stream 的服务器到客户端单向连接。该端点会先流式传输所有匹配过滤条件的既有实体，然后随着实体创建、修改或删除持续交付更新，让客户端维护通用作战图 (COP) 的实时视图。服务器首先为流打开前已存在且匹配过滤条件的所有 live 实体发送 PREEXISTING 类型事件，然后为新建实体发送 CREATE 事件，为现有实体变更发送 UPDATE 事件，为移除实体发送 DELETED 事件。除非 preExistingOnly 设为 true，否则流会无限期保持打开。可通过 heartbeatIntervalMS 参数配置 heartbeat 消息来维护连接健康并检测断连。这些 heartbeat 有助于保持连接，并让客户端确认服务器仍有响应。客户端可使用 componentsToInclude 参数指定需要填充的实体组件，以优化带宽使用，从而只接收相关数据而不是完整实体。连接会从临时断连中自动恢复，并从上次位置继续流式传输。与轮询方式不同，它能以更低延迟和更低服务器负载提供实时更新。

### 认证

- `Authorization` — _Bearer_ — Bearer 认证，格式为 `Bearer <token>`，其中 token 是你的认证令牌。

### 请求

此端点需要一个对象。

- `heartbeatIntervalMS` — _integer · optional_ — 发送 heartbeat 事件的间隔，默认 30 秒。

- `preExistingOnly` — _boolean · optional_ — 仅流式传输环境中的既有实体，然后关闭连接；默认值为 false。

- `componentsToInclude` — _list of strings · optional_ — 要包含的组件列表；留空表示包含所有组件。

- `filter` — _object · optional_ — Statement 过滤表达式树的可选根节点。如果提供，则只流式传输匹配过滤条件的实体。该过滤会动态应用：开始匹配的实体会作为 CREATE 交付，不再匹配的实体会作为 DELETE 交付。与 gRPC StreamEntityComponents 端点上的过滤器一致。

### 响应

返回所有既有数据，然后在新数据可用时返回新数据。

- `heartbeat` — _object_

或

- `entity` — _object_ — 表示某类实体变更的事件。

### 错误

400

Bad Request 错误

401

Unauthorized 错误
