# Lattice API

借助 SDK 及其开放数据模型，Lattice 让你可以把高度可定制的数据系统和硬件平台接入 Lattice 不断扩展、经过现场验证的稳健集成生态。

Lattice 提供以下 API：

实体

实体用于建模世界中对操作员有意义的任何事物。

任务

任务分配让你可以向连接到 Lattice 的 agent 发送顺序命令。

对象

对象让你可以在 Lattice 中存储分布式二进制数据。

## API 可用性

Lattice API 标记三种可用性级别：**beta**、**generally available (GA)** 和 **deprecated**：

API 版本管理策略

- 标记为 beta 的资源不应在生产环境中依赖。
- 标记为 beta 的资源可能在不通知的情况下发生破坏性变更。
- 标记为 beta 的资源可能并非在所有 Anduril 环境中可用。
- 未标记为 beta 的资源通常为 GA，并保持稳定性。

对于 [REST](/reference/rest/entities/publish-entity)，仍在开发中的 REST API 会在参考文档中标记为 beta：

对于 [gRPC](/reference/grpc/entitymanager-v1/publish-entity)，仍在开发中的 API 会在命名空间中带有 beta 标记。例如 `anduril.entitymanager.v2beta`。

## Lattice SDK 版本

不同语言的 Lattice SDK 独立进行版本管理。这些版本遵循语义化版本标准。例如在版本 `2.6.4` 中，`2` 是 *major*，`6` 是 *minor*，`4` 是 *patch*。发布新版 SDK 时，我们会根据引入的变更类型递增其中一个值。

- Major：当版本包含与前一版本不向后兼容的破坏性变更时递增 major 版本。例如修改某个方法。
- Minor：当版本包含与前一版本向后兼容的新功能时递增 minor 版本。例如新增某个方法。
- Patch：当版本包含向后兼容的 bug 修复时递增 patch 版本。例如修复实体未正确发布的问题。

SDK 版本管理策略

新的 Lattice SDK major 版本发布后，前一个 major 版本会继续获得 **六** 个月的关键安全修复支持。

如果你仍在使用较旧的 major SDK 版本，建议升级到最新 major 版本，以获得新功能和 bug 修复。旧 major 版本的软件包仍可继续使用，但不会再收到额外更新。

#### v1 到 v2

从 Lattice SDK v1 迁移到 v2+ 的主要变化是客户端改为从 REST 端点生成，而不是从 gRPC 端点生成。此迁移可参考专门的[迁移指南](/reference/overview/versioning/migrating-to-v2)。
