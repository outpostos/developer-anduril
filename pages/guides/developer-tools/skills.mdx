# Lattice SDK 技能

技能通过为 coding agent 提供专门知识和可重复工作流来扩展其能力。

## 安装

### Codex

安装包含技能并会自动更新的[插件](https://github.com/anduril/lattice-sdk-ai)：

```
codex plugin marketplace add anduril/lattice-sdk-ai
codex plugin add lattice-plugin@lattice-sdk-ai
```

### 手动安装

在你的项目中运行此命令：

```
npx skills add anduril/lattice-sdk-ai/lattice-plugin
```

这种方式不会自行更新。如果需要新版技能，请重新运行 `npx skills update -y`。

## 为什么需要技能？

随着更多合作伙伴接入公开 Lattice SDK，我们看到越来越多开发者使用 Codex 这类 coding agent 编写集成。我们希望为这些开发者提供 agent 优先的开发者工具，让他们尽可能快速、有效地创建 Lattice 集成。

借助技能，我们可以为 coding agent 扩展：

- 领域专业知识：就像一位 Lattice 专家在每一步都陪你一起工作。
- 可重复工作流：你不必每次都重复提供相同的 Lattice 集成说明。技能会预先提供上下文，让 agent 对任务有更整体的理解。

## 工作原理

技能基于渐进式披露的思路运行：

- 发现：最初，coding agent 只拥有每个技能文件的名称和描述。
- 激活：如果 coding agent 的任务匹配某个技能的描述，agent 会将该 `SKILL.md` 加载到上下文中。
- 执行：当 agent 带着 `SKILL.md` 上下文实现任务时，可以按需加载技能的其他部分，例如 `references/`。

渐进式披露对 coding agent 很重要，因为底层 LLM 的上下文窗口是有限资源。它让我们可以向 agent 提供足够上下文，而不必把信息塞满有限窗口，避免引发 [context rot](https://www.trychroma.com/research/context-rot) 等问题。

## 如何评估技能

我们会在内部 agent benchmark 中，让安装了插件的 coding agent 运行多种 Lattice 集成场景，以评估 agent 在安装插件后的表现。随着 benchmark 持续运行，我们会发现 agent 表现中的差距，并持续改进插件，以获得更好的 agent 体验。
