# 重试连接

生产集成会通过可能断开连接、限制流量或返回瞬时错误的网络发送数千个请求。可复用的重试工具让你能在每次 API 交互中应用一致的退避策略，而不是为每个调用重复编写重试逻辑。

## 开始之前

- 完成设置中的步骤，配置环境并安装 SDK。
- 决定使用 REST 还是 gRPC，因为错误类型和可重试代码会因协议而异。

gRPC 认证

如果你将 gRPC 与客户端凭证一起使用，请在运行本页示例前[设置令牌刷新模块](/guides/getting-started/authenticate#using-grpc)。

## SDK 会重试什么

构建自己的工具前，请先了解 SDK 已经处理了什么，避免对同一错误重试两次。

**Lattice REST SDK** 会在 HTTP `5xx`、`408`、`409` 和 `429` 响应上自动重试。SDK 重试机制使用从 1 秒开始、最大 60 秒且带 ±20% 抖动的指数退避，并遵循 `Retry-After`、`retry-after-ms` 和 `X-RateLimit-Reset` header。默认每次调用重试 2 次。可以通过 `request_options={"max_retries": N}` 按调用覆盖。

**gRPC SDK** 不会自动实现重试。你必须为 Lattice 集成自行实现重试。

避免双重重试

如果在 Lattice REST SDK 之上构建重试工具，请在每个 SDK 调用上设置 `request_options={"max_retries": 0}`，将整个重试策略委托给你的工具。否则，两层会独立重试，一个瞬时错误最多可能触发 `(sdk_retries + 1) x utility_retries` 次总尝试。

## 构建重试工具

用单个辅助函数包装任何 API 调用，可以集中调整退避参数、调整错误分类，并为整个集成添加可观测性：

1

### 定义重试函数

下列工具最多循环 `max_retries` 次，并在两次尝试之间按指数增长的退避时间休眠。对于重试无法修复的错误，它会立即重新抛出。

```
from anduril import Lattice, \
    Aliases, MilView, Location, Position, Ontology, Provenance
from anduril.core import ApiError
from datetime import datetime, timezone, timedelta
import asyncio
import httpx
import math
import os
import sys
from uuid import uuid4

lattice_endpoint = os.getenv('LATTICE_ENDPOINT')
client_id = os.getenv('LATTICE_CLIENT_ID')
client_secret = os.getenv('LATTICE_CLIENT_SECRET')

# Remove sandboxes_token from the following statements if you are not developing on Sandboxes.
sandboxes_token = os.getenv('SANDBOXES_TOKEN')
if not client_id or not client_secret or not lattice_endpoint or not sandboxes_token:
    print("Missing required environment variables.")
    sys.exit(1)

client = Lattice(
    base_url=f"https://{lattice_endpoint}",
    client_id=client_id,
    client_secret=client_secret,
    # Remove the following header if you are not developing on Sandboxes.
    headers={ "anduril-sandbox-authorization": f"Bearer {sandboxes_token}" }
)

MAX_RETRIES = 3
INITIAL_BACKOFF_SECONDS = 1.0

TERMINAL_STATUS_CODES = {400, 401, 403, 413}

async def retry_with_backoff(operation, *, max_retries=MAX_RETRIES, initial_backoff=INITIAL_BACKOFF_SECONDS):
    for attempt in range(max_retries):
        try:
            return operation()
        except ApiError as e:
            # Terminal 4xx errors mean the request itself is wrong; retrying will not help.
            if e.status_code in TERMINAL_STATUS_CODES:
                raise
            if attempt < max_retries - 1:
                backoff = initial_backoff * (2 ** attempt)
                await asyncio.sleep(backoff)
            else:
                raise
        except (httpx.ConnectError, httpx.RemoteProtocolError):
            if attempt < max_retries - 1:
                backoff = initial_backoff * (2 ** attempt)
                await asyncio.sleep(backoff)
            else:
                raise

entity_id = str(uuid4())
radius_degrees = 0.1
creation_time = datetime.now(timezone.utc)
count = 0.0

def publish_track():
    global count
    count += 0.1
    t = math.radians(count)
    latest_timestamp = datetime.now(timezone.utc)

    client.entities.publish_entity(
        entity_id=entity_id,
        description="Friendly airplane",
        is_live=True,
        aliases=Aliases(
            name="Airplane 1"
        ),
        created_time=creation_time,
        expiry_time=latest_timestamp + timedelta(minutes=5),
        ontology=Ontology(
            template="TEMPLATE_TRACK",
            platform_type="Airplane"
        ),
        mil_view=MilView(
            disposition="DISPOSITION_FRIENDLY",
            environment="ENVIRONMENT_AIR"
        ),
        location=Location(
            position=Position(
                latitude_degrees=50.91402185768586 + (radius_degrees * math.cos(t)),
                longitude_degrees=0.79203612077257 + (radius_degrees * math.sin(t))
            )
        ),
        provenance=Provenance(
            integration_name="your_integration_name",
            data_type="your_data_type",
            source_update_time=latest_timestamp
        ),
        # The utility owns the retry policy, so disable the SDK's built-in retry layer to avoid double-retrying.
        request_options={"max_retries": 0}
    )

async def app():
    try:
        while True:
            await retry_with_backoff(publish_track)
            print(f"Published track with entity ID: {entity_id}")
            await asyncio.sleep(5)
    except asyncio.CancelledError:
        print(">>>Exiting...")
    except Exception as error:
        print(f"Exception: {error}")

if __name__ == "__main__":
    asyncio.run(app())
```

### 对要重试的错误分类

并非所有错误都能从重试中受益。重试格式错误的请求或未授权调用会浪费时间，并可能掩盖 bug。决定退避或立即重新抛出前，请将错误分为两类：**可重试**和**终止**。

**REST SDK**

该工具会捕获两大类错误：

- 带有 status_code 的 anduril.ApiError - 检查代码以决定。
- httpx.ConnectError 和 httpx.RemoteProtocolError - 底层传输失败，始终可重试。

应重试的可重试状态码：

- 404 Not Found - 资源可能因最终一致性尚不可见。
- 408 Request Timeout - 服务器未及时收到完整请求，通常由瞬时网络延迟导致。
- 409 Conflict - 并发写入与该请求竞争，因此短暂退避后重试通常会成功。
- 429 Too Many Requests - 客户端被限流，因此应先退避再重试。
- 5xx Server Error - 服务器遇到瞬时故障，后续尝试可能恢复。

**不应**重试的终止状态码：

- 400 Bad Request - 载荷格式错误。
- 401 Unauthorized - 重试前刷新凭证。
- 403 Forbidden - 重试不会改变权限。
- 413 Payload Too Large - 减小载荷大小。

**gRPC SDK**

使用 `status.Code(err)` 提取 gRPC 状态码，并根据 `map[codes.Code]bool` 检查。

应重试的可重试代码：

- UNAVAILABLE - 服务器暂时不可达。
- DEADLINE_EXCEEDED - 调用在收到响应前超时。
- RESOURCE_EXHAUSTED - 客户端被限流或超出配额。
- INTERNAL - 服务器遇到未指定故障，可能是瞬时故障。
- ABORTED - 发生并发冲突，因此短暂退避后重试通常会成功。
- UNKNOWN - 返回了无法识别的错误，因此按瞬时错误处理。
- NOT_FOUND - 资源可能因最终一致性尚不可见。

**不应**重试的终止代码：

- INVALID_ARGUMENT - 重试前修复请求。
- PERMISSION_DENIED - 重试不会授予访问权限。
- UNAUTHENTICATED - 重试前刷新令牌。
- FAILED_PRECONDITION - 必需前置条件未满足。
- ALREADY_EXISTS - 资源已存在。

### 将工具应用到任何 API 调用
