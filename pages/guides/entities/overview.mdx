# 实体概览

**实体**是支撑 Lattice 通用作战图 (COP) 的可互操作数据结构。

实体由**组件**组成。决定实体是什么以及应如何与其交互的，是组件是否存在，而不是严格的类型层级。可以把实体理解为一袋可按需混合搭配的组件。实体在不同时间点可能不完整，这反映了 COP 的实时状态。局部状态对态势感知很有价值，因此你的代码必须稳健处理缺失组件。

组合原则

- 组件不得重复 - 避免在两个不同组件上建模同一底层数据。
- 组件是非层级化的 - 数据模型是可组合的，而不是继承树。

## 实体模型

实体需要下列组件：

- `entity_id` _StringRequired_
  唯一字符串标识符。可以是全局唯一标识符 (GUID)。

- `is_live` _BooleanRequired_
  布尔值。设为 `true` 时创建或更新实体。如果实体仍处于 live 状态时将其设为 `false`，则会触发 `DELETE` 事件。

- `expiry_time` _DatetimeRequired_
  实体过期的未来时间，必须小于 30 天。当 `expiry_time` 已过，Lattice 会删除该实体。

- `provenance.integration_name` _stringRequired_
  创建该实体的集成名称。

- `aliases.name` _string_
  表示实体名称的人类可读字符串。

更多信息请参阅 *Lattice API Reference* 中的 [Entities](/reference/rest/entities/publish-entity#request)。

## 实体模板

虽然没有严格的类型层级，用户界面仍可以根据实体的[本体](/reference/rest/entities/publish-entity#ontology.template)组件对实体分组。Lattice 支持下列三种顶层实体形态：

资产

航迹

地理实体

### 资产

*资产*是由你控制，或由其他操作员或系统控制的实体。资产可以接受搜索或跟踪等任务。要创建资产，除必需组件外，还需要添加下列组件：

- `ontology` _OntologyRequired_
  添加本体组件，并将 [`template`](/reference/rest/entities/publish-entity#request.body.ontolog.template) 设置为 `TEMPLATE_ASSET`，以在 Lattice 中渲染资产。

- `location` _LocationRequired_
  添加 [location](/reference/rest/entities/publish-entity#request.body.location) 组件，并使用纬度和经度详情设置资产位置。

- `milView` _MilViewRequired_
  添加 [milView](/reference/rest/entities/publish-entity#request.body.milView) 组件，并设置资产的敌我属性、环境域和国籍。

### 航迹

*航迹*表示由连接到 Lattice 的资产或集成跟踪的任何实体。航迹不直接受友方力量控制。这包括来自雷达或传感器的飞机航迹、信号探测，以及通过摄像头探测到的车辆、人员或动物。

Lattice 支持下列航迹类型：

航迹

传感器关注点 (SPI)

关注信号 (SOI)

- `ontology` _Required_
  添加本体组件，并将 [`template`](/reference/rest/entities/publish-entity#request.body.ontolog.template) 设置为 `TEMPLATE_TRACK`，以渲染通用航迹。

- `location` _Required_
  添加 [`location`](/reference/rest/entities/publish-entity#request.body.position) 组件，以设置航迹的纬度和经度。

- `milView` _Required_
  添加 [`milView`](/reference/rest/entities/publish-entity#request.body.milView) 组件，以设置航迹的敌我属性、环境域和国籍。

### 地理实体

*地理实体*是在地图上绘制的形状、区域或关注点。使用地理实体表示任何感兴趣的地理区域，例如供自主车辆运行的机场或控制区。

- `ontology.template` _Required_
  添加本体组件，并将 [`template`](/reference/rest/entities/publish-entity#request.body.ontolog.template) 设置为 `TEMPLATE_GEO`，以渲染地理实体形状。

- `geo_details` _Required_
  添加 [`geo_details`](/reference/rest/entities/publish-entity#request.body.geoDetails) 组件。

- `geo_shape` _Required_
  添加 [`geo_shape`](/reference/rest/entities/publish-entity#request.body.geoShape) 组件。

- `location`
  如果 `geo_shape` 设置为 [ellipse](/reference/rest/entities/publish-entity#request.body.geoShape.ellipse)，请添加 [`location`](/reference/rest/entities/publish-entity#request.body.location) 组件。

## 实体生命周期

实体具有明确定义的**创建**、**更新**和**删除**生命周期。每次生命周期更新时，Entity Manager 都会向 Lattice 发出状态变更事件：

1

### 创建

当应用或集成发布实体时，Lattice 会发出状态变更事件，将实体状态设置为 `CREATE`。

2

### 更新

当实体中的数据变化时，Lattice 会将状态变更作为**更新**事件发出。为了优化性能，Lattice 依赖 `provenance.source_update_time` 的变化来触发更新。它*不会*比较完整 proto 定义来设置状态变更。

3

### 删除

当实体的 `expiry_time` 已过，或发送了将 `is_live` 组件设为 `false` 的更新时，实体会被删除。或者，你可以使用 `noExpiry` 标志创建无限期持久存在的实体。只有当实体包含应在其即时作战上下文之外供其他任务或集成使用的信息时，才使用 `noExpiry`，例如长生命周期地理实体。

持久性

- 如果同时设置了 `noExpiry` 和 `expiryTime`，Lattice 会忽略 `expiryTime`。
- 如果发生服务重启，且实体在此前 5 分钟内未被重新发布，则无论 `noExpiry` 如何设置，该实体都不会被恢复。

你应通过移除内存中对该实体的所有引用，或从用户界面中丢弃它，来处理删除事件。
