# 定义任务

本指南介绍编写自定义任务定义并在 Lattice 中使用的最佳实践。自定义任务定义允许你用自己的专门工作流扩展 Lattice 的任务能力。

## 开始之前

- 熟悉 Lattice 中的任务。
- 要创建任务，请设置 Lattice 环境。
- 复习 Protobuf files and packages 指南，了解 Protobuf 基础。

## 编写任务

自定义任务是一个 Protobuf 消息类型，包含资产自主执行任务所需的信息。任务定义的复杂度取决于集成需求。例如：

- 简单任务：传感器可以定义开/关切换消息
- 面向实体的任务：跟踪系统可以定义包含要跟踪的 entity_id 的消息
- 复杂任务：自主车辆可以定义多个参数，包括航点、速度限制、传感器配置和优先级

自定义任务让你能够灵活建模特定领域工作流，同时在 Lattice 部署中保持类型安全和兼容性。

最简单的任务定义是单个 Protobuf 消息。例如，下面的 schema 定义了一个打开传感器的任务：

```proto
syntax = "proto3";

package org.example.sensor.v1;

// Turn the sensor on.
message SensorOn {}
```

接下来，你将了解如何将定义组织到 [package](#create-a-package) 中、Lattice 如何[识别它们](#fully-qualified-names)，以及如何建模[更丰富的任务参数](#define-a-custom-schema)。

## 创建 package

将任务定义为 package 中的 Protobuf 消息。package 应包含所有相关消息类型，用于组合表达集成能力的任务。清晰、准确地命名 package 对避免潜在命名冲突至关重要。

使用一致的 package 命名模式：`org.repository.package.version`

其中：

- org：你在 Schema Registry 中的组织名称。
- repository：你在 Schema Registry 中的仓库名称。
- package：任务领域的描述性名称，例如 reconnaissance、navigation 或 sensor。
- version：API 版本，例如 v1、v2、v1alpha 或 v2test。

```
// Example
package company.isr.imaging.v1test;
```

在早期开发期间，请在版本后追加稳定性标记（`alpha`、`beta` 或 `test`），将 package 标记为不稳定。

```
package org.example.reconnaissance.v1beta;
package org.example.navigation.v2beta;
```

Schema Registry 会对所有 package 强制执行破坏性变更检测，无论是否有稳定性标记。如果需要进行破坏性变更，必须创建新版本。

### 完全限定名

消息的完全限定名由 package 和消息名组成：

```proto
package org.example.reconnaissance.v1beta;

message Objective {
  // ...
}
```

上述消息生成的名称为：`org.example.reconnaissance.v1beta.Objective`。

所有 protobuf 类型 URL 都以 `type.googleapis.com` 为前缀。你始终会通过类型 URL 引用任务定义，例如：`type.googleapis.com/org.example.reconnaissance.v1beta.Objective`。

全局唯一名称

每个完全限定消息名在 Schema Registry 中都必须全局唯一。这可防止多个组织发布 schema 时发生命名冲突。

这个类型 URL 也是你在资产上公开任务的方式。Entity 模型的 [`taskCatalog`](/reference/rest/entities/publish-entity#request.body.taskCatalog) 会列出资产可以执行的任务，每个条目的 `taskSpecificationUrl` 都是某个任务定义的类型 URL：

```
"taskCatalog": {
    "taskDefinitions": [
        {
            "taskSpecificationUrl": "type.googleapis.com/org.example.reconnaissance.v1beta.Objective"
        }
    ]
}
```

只有当资产的 `taskCatalog` 公开了某个任务的类型 URL 时，操作员才能将该任务分配给该资产。要了解如何发布带有 `taskCatalog` 的资产并处理其收到的任务，请参阅[集成 agent](/guides/tasks/integrate-an-agent)。

有关 Protobuf package 和命名的更多信息，请参阅 Buf 文档中的 [Protobuf files and packages](https://buf.build/docs/reference/protobuf-files-and-packages/)。

## 破坏性变更保护

Schema Registry 会对所有 package 强制执行破坏性变更检测。这可确保 schema 消费者的向后兼容性。你可以弃用旧字段，必要时也可以发布 package 的新版本。

| 破坏性变更（阻止） | 非破坏性变更（允许） |
| --- | --- |
| 移除或重命名字段 | 添加新字段 |
| 更改字段类型 | 添加新的枚举值 |
| 更改字段编号 | 添加新消息 |
| 移除枚举值 | 弃用字段（使用 `deprecated` 选项） |

有关破坏性变更的完整指南，请参阅 [Buf breaking change detector documentation](https://buf.build/docs/breaking/overview/)。

## 定义自定义 schema

Lattice 中的每个任务都由 `Task` 消息表示。它的 `specification` 字段是 [`google.protobuf.Any`](https://protobuf.dev/reference/protobuf/google.protobuf/#any)，让 Lattice 可以承载任何自定义任务类型，而无需预先知道其 schema：

```proto
message Task {
  // Version of this task.
  TaskVersion version = 1;

  // The path for the Protobuf task definition, and the complete task data.
  // Your custom task message is packed into this Any field.
  google.protobuf.Any specification = 3;

}
```

创建任务时，Lattice 会将你定义的消息打包到这个 `specification` 字段中。要编写示例自定义任务，请创建新的 `.proto` 文件。例如：

```proto
syntax = "proto3";

package org.example.reconnaissance.v1beta;

// LLA is a geodetic position (latitude, longitude, altitude).
message LLA {
  // Latitude in degrees.
  double latitude_degrees = 1;

  // Longitude in degrees.
  double longitude_degrees = 2;

  // Altitude in Height Above Ellipsoid (WGS84) in meters.
  double altitude_hae_m = 3;
}

// Objective represents the target of a reconnaissance task. The target is
// either an entity to reconnoiter or a fixed geodetic point.
message Objective {
  oneof target {
    // Entity to reconnoiter, identified by its entity ID.
    string entity_id = 1;

    // Fixed geodetic point to reconnoiter.
    LLA lla = 2;
  }
}
```

最佳实践

- 使用描述性注释：为每个字段和枚举值编写文档，帮助其他开发者理解你的 schema。
- 使用 wrapper 类型：对于可选数值字段，请使用 google.protobuf.*Value wrapper 类型，而不是原始类型。
- 从稳定性标记开始：开发期间使用 v1alpha 或 v1beta，以允许破坏性变更。
- 保留字段 0：始终将枚举值 0 保留给 INVALID 或 UNSPECIFIED 变体。在 proto3 中，未设置的枚举字段默认为 0，因此保留它可以避免有意设置的值与未设置状态无法区分。

## 常见模式

航迹实体

```proto
syntax = "proto3";

package company.sensor.v1;

// Use the entity_id field task your Asset against an Entity
message TrackEntity {
    string entity_id = 1;
}
```

任务参数

```proto
syntax = "proto3";

package company.uas.v1;

// Use Message types to compose a more complex Task
message Coordinate {
    double lat = 1;
    double lon = 2;
}

// A target could be either a lat/lon, or an Entity that we can track
message Target {
    oneof target {
        string entity_id = 1;
        Coordinate coordinate = 2;
    }
}

message FlightConstraints {
    float min_altitude_agl_m = 1;
    float max_altitude_agl_m = 2;
    float max_ias_kts = 3;
    float min_ias_kts = 4;
}

enum FlightPattern {
    FLIGHT_PATTERN_GRID = 1;
    FLIGHT_PATTERN_ORBIT = 2;
    FLIGHT_PATTERN_SECTOR_SEARCH = 3;
}

// Task Message
message Survey {
    Target target = 1;
    FlightPattern flight_pattern = 2;
    FlightConstraints flight_constraints = 3;
}
```
