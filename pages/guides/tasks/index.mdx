# 任务概览

[任务模型](/reference/rest/tasks/create-task)是一种数据结构，用于建模操作员可在一个资产或一组资产上执行的有意、顺序动作。

**可任务化 agent** 是可以接受并执行任务的服务、资产、组或人员。例如，你可以给机器人分配任务，让它调查特定区域。

**Tasks** API 管理任务生命周期，并将任务路由到可任务化 agent，让你能够创建、更新、监控和执行任务。Task Manager 管理任务在 Lattice 中的分发和持久化。agent 处理任务时会更新任务状态。Task Manager 会在通用作战图中维护任务的最新状态。

## 任务模型

任务由下列必需组件组成：

- `description` _stringRequired_
  任务描述。用它概述任务目标，以及被分配执行任务的 agent。

- `specification` _stringRequired_
  完整 JSON 定义，以字符串形式设置任务目标和参数。

- `version` _stringRequired_
  任务版本。

- `created_by` _stringRequired_
  发起任务的集成或操作员记录。

- `last_updated_by` _stringRequired_
  最后更新任务的集成或操作员记录。

## 任务目录

要让 Lattice 知道你的 agent 可以完成特定任务，请在实体的 [`TaskCatalog`](/reference/rest/entities/publish-entity#request.body.taskCatalog) 组件中添加 `TaskDefinitions`：

- `taskDefinitions.taskSpecificationUrl` _string_
  设置 agent 可以执行的特定任务定义 URL。必须以 `type.googleapis.com/` 为前缀：`VisualId` 任务可能涉及识别或跟踪视觉目标。

请与 Anduril 代表协作确定适用于你用例的任务定义列表。

例如，下列 `VisualId` 任务可能涉及识别或跟踪视觉目标：

```
"taskCatalog": {
    "taskDefinitions": [
        {
            "taskSpecificationUrl": "type.googleapis.com/anduril.tasks.v2.VisualId"
        }
    ]
}
```

## 任务状态

TaskManager API 让操作员和 agent 能够跟踪并更新任务生命周期。要配置应用更新任务状态，请使用 [`UpdateTaskStatus`](/reference/rest/tasks/update-task-status) API 方法并指定下列组件：

- `status.status` _Status_
  表示 agent 上报的任务生命周期阶段。即 [`taskStatus` 组件](/reference/rest/tasks/get-task#response.body.status)。更多信息请参阅[监听任务](/guides/tasks/integrate-an-agent)。

- `status.task_error` _TaskError_
  包含执行任务期间发生的任何错误。

- `status.progress` _string_
  表示任务的增量进度，应来自任务的 `/v*/progress` 文件夹。

- `status.result` _string_
  表示任务结果，应来自任务的 `/v*/result` 文件夹。

- `status.start_time` _Timestamp_
  表示任务开始执行的时间。

- `status.estimate` _string_
  对任务将如何推进的任何估计，应来自 `tasks/v*/estimates` 文件夹。

- `status.allocation` _Allocation_
  包含正在被用于执行任务的 agent 列表。

## 任务生命周期

任务具有明确定义的生命周期：**创建**、**更新**和**删除**。在任务生命周期的每个阶段，Lattice 都会向环境发出状态变更事件，提升态势感知：

1

### 创建

首次创建任务时，Lattice 会将任务状态设置为 `STATUS_SENT`。分配到该任务的 agent 随后可以监听、接收并执行该任务。

2

### 更新

当 agent 朝任务总体目标推进时，它会更新 Lattice 中的任务状态，并递增任务状态版本。

3

### 完成

agent 完成任务后，会将任务状态设置为两个终止状态之一：任务成功则为 `STATUS_DONE_OK`，任务失败则为 `STATUS_DONE_NOT_OK`。处于上述任一终止状态的任务无法再更新。
