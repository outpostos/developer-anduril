# 指挥 agent 并操作任务

操作员使用 Tasks API 在其作战域内创建、监控和管理任务。

你在 Lattice 中指挥和监控的具体任务取决于任务需求以及你正在集成的环境。本页展示如何使用 Lattice Sandboxes 创建、监控和取消任务。

`CreateTask`（[REST](/reference/rest/tasks/create-task)）API 让你可以使用发布到 Lattice Schema Registry 的自定义任务定义，在 Lattice 中创建任务。`StreamTasks`（[REST](/reference/rest/tasks/stream-tasks) | [gRPC](/reference/grpc/taskmanager-v1/stream-tasks)）API 为环境中的所有任务创建、更新和状态变化提供集中可见性。`CancelTask`（[REST](/reference/rest/tasks/cancel-task) | [gRPC](/reference/grpc/taskmanager-v1/cancel-task)）API 允许你请求取消不再需要的任务。

## 开始之前

- 要创建、监控或取消任务，请设置 Lattice 环境。
- 熟悉任务和任务生命周期。
- 要创建自定义任务，请将 schema 发布到 Lattice Schema Registry (LSR)。

## 使用 REST 创建任务

使用 REST 处理自定义任务时：

1. 首先，从 Schema Registry 检索 JSON Schema 定义。
2. 然后，使用这些 schema 定义验证任务数据。
3. 最后，使用验证后的数据通过 CreateTask API 在 Lattice 中创建任务。

Lattice Schema Registry (LSR) 让你可以使用 JSON schema 验证任务数据：

1

使用凭证登录 [LSR](https://schema-registry.developer.anduril.com/)。

2

导航到组织的仓库。

3

选择包含自定义任务定义的仓库。

4

浏览到要用于任务的特定 protobuf 定义。

5

选择插件下拉菜单并选择 JSON Schema，以查看可用的 JSON Schema 文件。

6

下载 JSON schema 文件：

```bash
curl -H "Authorization: Bearer $BUF_TOKEN" \
     -o myschema.jsonschema.bundle.json \
     https://schema-registry.developer.anduril.com/plugins/<your-organization>/<your-repository>/<your-schema>/jsonschema/bundle
```

该命令会下载包含所有被引用 schema 的打包 JSON Schema 文件。例如：自定义任务的 JSON Schema 结构示例：

```json
{
  "$id": "org.example.reconnaissance.v1beta.Objective.jsonschema.json",
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "properties": {
    "entityId": {
      "type": "string"
    },
    "lla": {
      "$ref": "org.example.reconnaissance.v1beta.LLA.jsonschema.json"
    }
  },
  "type": "object"
}
```

要使用自定义任务定义创建任务，请执行以下操作：

1

### 准备任务数据

定义与你的 schema 结构匹配的自定义任务数据。该数据会封装在 [`CreateTaskRequest`](/reference/rest/tasks/create-task#request) 消息的 [`specification`](/reference/rest/tasks/create-task#request.body.specification) 字段中。

```
task_data = {
    "lla": {
        "latitudeDegrees": 37.7749,
        "longitudeDegrees": -122.4194,
        "altitudeHaeM": 100.0
    }
}
```

2

### 使用 schema 验证任务数据

向 Lattice 发送数据前，请根据 JSON Schema 进行验证，确保它与你的自定义任务定义匹配。这可以避免向 API 提交无效任务数据时出现问题。

```
#!/usr/bin/env python3
import asyncio
import json
import os
import sys
from anduril import Lattice
from anduril import (
    GoogleProtobufAny,
    Principal,
    Relations,
    System,
    TaskEntity
)
from jsonschema import validate  # type: ignore[import-untyped]

# Load environment variables
lattice_endpoint = os.getenv('LATTICE_ENDPOINT')
environment_token = os.getenv('ENVIRONMENT_TOKEN')
sandboxes_token = os.getenv('SANDBOXES_TOKEN')  # Remove if not using Sandboxes

if not environment_token or not lattice_endpoint:
    print("Missing required environment variables.")
    sys.exit(1)

# Initialize Lattice client
client = Lattice(
    base_url=f"https://{lattice_endpoint}",
    token=lambda: environment_token,  # type: ignore[arg-type]
    # Remove the following header if not developing on Sandboxes
    headers={"anduril-sandbox-authorization": f"Bearer {sandboxes_token}"} if sandboxes_token else None
)

def load_schema(schema_file):
    """Load a JSON schema from file."""
    with open(schema_file, 'r') as f:
        return json.load(f)

def validate_task_data(task_data, schema_file):
    """Validate task data against a JSON schema."""
    schema = load_schema(schema_file)

    try:
        validate(instance=task_data, schema=schema)
        print("Task data validation successful")
        return True
    except Exception as e:
        print(f"Validation error: {str(e)}")
        return False

async def create_task(task_data, agent_id, entity_id=None):
    """
    Create a new task using the Lattice SDK.

    Args:
        task_data: The validated task data
        agent_id: The entity ID of the agent to route the task to for execution
        entity_id: Optional entity ID to use as the initial entity
    """
    description = "Custom Task Definition"
    specification_type = "type.googleapis.com/org.example.reconnaissance.v1beta.Objective"
    specification = GoogleProtobufAny(
        type=specification_type,
        **task_data
    )
    author = Principal(system=System(service_name="example-service"))
    # Route the task to the agent by setting it as the assignee.
    relations = Relations(assignee=Principal(system=System(entity_id=agent_id)))

    try:
        # Set up initial entities if an entity ID was provided
        initial_entities = None
        if entity_id:
            try:
                print(f"Fetching entity with ID: {entity_id}")
                entity = client.entities.get_entity(entity_id)

                if entity:
                    task_entity = TaskEntity(entity=entity)
                    initial_entities = [task_entity]
                    print(f"Using entity {entity_id} as initial entity for task")
            except Exception as e:
                print(f"Error fetching entity {entity_id}: {str(e)}")

        # Create the task with the validated data
        print("Creating task...")
        response = client.tasks.create_task(
            description=description,
            specification=specification,
            author=author,
            relations=relations,
            is_executed_elsewhere=False,
            initial_entities=initial_entities
        )

        if response.version:
            print(f"Task created successfully with ID: {response.version.task_id}")
        return response
    except Exception as e:
        print(f"Error creating task: {str(e)}")
        return None

async def main():
    # Example task data for a reconnaissance objective: a fixed geodetic point.
    task_data = {
        "lla": {
            "latitudeDegrees": 37.7749,
            "longitudeDegrees": -122.4194,
            "altitudeHaeM": 100.0
        }
    }

    # Path to the JSON schema file (downloaded from Schema Registry)
    schema_file = 'org.example.reconnaissance.v1beta.Objective.jsonschema.bundle.json'

    # Validate the task data (skip if schema file not found)
    if os.path.isfile(schema_file):
        if not validate_task_data(task_data, schema_file):
            print("Task creation aborted due to validation errors.")
            return
    else:
        print("Schema file not found, skipping validation")

    # Create the task with validated data
    # Replace with the entity ID of the agent to route the task to.
    agent_id = "<AGENT_ID>"
    # You can pass an entity_id here if you want to associate the task with an entity
    entity_id = None  # Replace with an actual entity ID if needed
    result = await create_task(task_data, agent_id, entity_id)
    if result:
        print(f"Task created with status: {result.status}")

if __name__ == "__main__":
    asyncio.run(main())
```

### 使用验证后的数据创建任务

使用 [`CreateTask`](/reference/rest/tasks/create-task) API 将任务提交到 Lattice。该 API 需要下列关键字段：

- description：任务的人类可读描述（最多 4096 个字符）。
- specification：包装在 Google Protocol Buffer Any 消息中的已验证任务数据。
- author：有关谁或什么创建了任务的信息。
- relations：任务关系，例如父任务或被分配者。将 relations.assignee 设置为 agent 的 Principal，以将任务路由给该 agent 执行。

## 使用 gRPC 创建任务

使用 gRPC 时，Protobuf 类型会直接从任务定义生成，因此没有单独的 JSON schema 验证步骤。相反，编译器会强制任务形态。你构建自定义任务消息，将其打包到 [`specification`](/reference/grpc/taskmanager-v1/create-task) `Any` 字段中，然后调用 `CreateTask`。

1

### 构建并打包任务 specification

使用从[任务定义](/guides/tasks/define-a-task)生成的绑定构造 `Objective` 消息，然后将其打包到 `google.protobuf.Any` 中。`Any` 上的类型 URL 让接收 agent 能够识别并解包任务：

```
# This Python example is compatible with artifacts generated using
# the following grpc/python plugin: https://buf.build/anduril/lattice-sdk/sdks/main:grpc/python

import os
import sys
import grpc
from auth import ClientCredentialsAuth

from google.protobuf.any_pb2 import Any

from anduril.taskmanager.v1.task.pub_pb2 import (
    Principal,
    Relations,
    System,
    User,
)
from anduril.taskmanager.v1.task_manager_api.pub_pb2 import CreateTaskRequest
from anduril.taskmanager.v1.task_manager_api.pub_pb2_grpc import TaskManagerAPIStub

# Your custom task from schema-registry.developer.anduril.com
from org.example.reconnaissance.v1beta.objective_pb2 import (
    LLA,
    Objective,
)

def create_task(client, agent_entity_id):
    """Create an Objective task and route it to an agent."""
    # Build the custom task message. Objective is a oneof; here we set an LLA point.
    objective = Objective(
        lla=LLA(
            latitude_degrees=37.7749,
            longitude_degrees=-122.4194,
            altitude_hae_m=100.0,
        ),
    )

    # Pack the task into a google.protobuf.Any for the specification field.
    specification = Any()
    specification.Pack(objective)

    request = CreateTaskRequest(
        description="Reconnaissance objective",
        specification=specification,
        # The service creating the task.
        author=Principal(user=User(user_id="operator@example.com")),
        # Route the task to the agent by setting it as the assignee.
        relations=Relations(assignee=Principal(system=System(entity_id=agent_entity_id))),
    )

    response = client.CreateTask(request)
    return response.task

def main():
    client_id = os.getenv("LATTICE_CLIENT_ID")
    client_secret = os.getenv("LATTICE_CLIENT_SECRET")
    lattice_endpoint = os.getenv("LATTICE_ENDPOINT")
    sandboxes_token = os.getenv("SANDBOXES_TOKEN")

    if not client_id or not client_secret or not lattice_endpoint or not sandboxes_token:
        print("Missing required environment variables", file=sys.stderr)
        sys.exit(1)

    auth = ClientCredentialsAuth(
        client_id=client_id,
        client_secret=client_secret,
        sandboxes_token=sandboxes_token,
        endpoint=f"https://{lattice_endpoint}/api/v1/oauth/token",
    )

    credentials = grpc.ssl_channel_credentials()
    channel = grpc.intercept_channel(
        grpc.secure_channel(lattice_endpoint, credentials),
        auth.create_metadata_interceptor(),
    )

    client = TaskManagerAPIStub(channel)

    # Replace with the entity ID of the agent to route the task to.
    agent_entity_id = "<AGENT_ID>"

    task = create_task(client, agent_entity_id)
    print(f"Created task with ID: {task.version.task_id}")

if __name__ == "__main__":
    main()
```

- specification：打包到 google.protobuf.Any 中的自定义任务消息。

- relations.assignee：agent 的 Principal。设置此字段以将任务路由给该 agent 执行。

## 监控任务

`StreamTasks`（[REST](/reference/rest/tasks/stream-tasks) | [gRPC](/reference/grpc/taskmanager-v1/stream-tasks)）API 会建立 server-sent events (SSE) 流，让你监控 Lattice 中的任务：

1

### 初始化任务流

在下列示例中，我们指定一个前缀来过滤任务流：

```
package main

import (
	"context"
	"fmt"
	"net/http"
	"os"

	Lattice "github.com/anduril/lattice-sdk-go/v4"
	"github.com/anduril/lattice-sdk-go/v4/client"
	"github.com/anduril/lattice-sdk-go/v4/option"
)

func main() {
	// Get environment variables
	latticeEndpoint := os.Getenv("LATTICE_ENDPOINT")
	clientSecret := os.Getenv("LATTICE_CLIENT_SECRET")
	clientId := os.Getenv("LATTICE_CLIENT_ID")
	sandboxesToken := os.Getenv("SANDBOXES_TOKEN")

	// Check required environment variables
	if latticeEndpoint == "" || clientId == "" || clientSecret == "" || sandboxesToken == "" {
		fmt.Println("Missing required environment variables")
		os.Exit(1)
	}

	// Initialize headers for sandbox authorization
	headers := http.Header{}
	headers.Add("Anduril-Sandbox-Authorization", fmt.Sprintf("Bearer %s", sandboxesToken))
	// Create the client
	LatticeClient := client.NewClient(
		option.WithClientCredentials(clientId, clientSecret),
		option.WithBaseURL(fmt.Sprintf("https://%s", latticeEndpoint)),
		option.WithHTTPHeader(headers),
	)

	fmt.Println("Starting task stream...")

	ctx := context.Background()

	// Create task stream request
	request := &Lattice.TaskStreamRequest{
		HeartbeatIntervalMs:     Lattice.Int(10000),
		ExcludePreexistingTasks: Lattice.Bool(false),
		TaskType: &Lattice.TaskStreamRequestTaskType{
			TaskStreamRequestTaskTypeTaskTypePrefix: &Lattice.TaskStreamRequestTaskTypeTaskTypePrefix{
				// Define a prefix filter for tasks that belong to your organization
				TaskTypePrefix: "type.googleapis.com/<your-organization>.tasks",
			},
		},
	}

	// Start the task stream
	stream, err := LatticeClient.Tasks.StreamTasks(ctx, request)
	if err != nil {
		fmt.Printf("Failed to start task stream: %v\n", err)
		return
	}
	defer stream.Close()

	// Process the stream events as they arrive
	for {
		event, err := stream.Recv()
		if err != nil {
			fmt.Printf("Error receiving task stream event: %v\n", err)
			return
		}

		if event.Event == "heartbeat" {
			// Process heartbeat events
			timestamp := *event.GetHeartbeat().GetTimestamp()
			fmt.Printf("Heartbeat: %v\n", timestamp)
		} else {
			task := event.GetTaskEvent().GetTaskEvent().GetTask()
			taskId := task.GetVersion().GetTaskID()
			status := task.GetStatus().GetStatus()

			fmt.Printf("  TaskID: %v\n", *taskId)
			fmt.Printf("  Status: %v\n", *status)
		}
	}
}
```

`StreamTasks` 方法接受下列参数：

- `heartbeatIntervalMs` _Number_
  服务器发送 heartbeat 事件的间隔，单位为毫秒（默认值：30000 ms）。使用 heartbeat 验证连接仍然活跃。最小值为 1000 ms；更小的值会提升为 1000 ms。

- `excludePreexistingTasks` _Boolean_
  设为 `true` 时，流只包含流启动后创建的任务。设为 `false`（默认值）时，现有任务也会包含在流中。

- `taskType` _Object_
  指定流中包含哪些任务类型。可以按精确匹配或前缀过滤。taskTypePrefixString 只包含类型以指定前缀开头的任务，例如 `type.googleapis.com/<your-organization.tasks>`。taskTypeUrlsList 只包含列表中指定的任务。对于要从流中过滤出的每个任务，必须列出任务定义的完整 URL。

2

```
	latticeEndpoint := os.Getenv("LATTICE_ENDPOINT")
	clientSecret := os.Getenv("LATTICE_CLIENT_SECRET")
	clientId := os.Getenv("LATTICE_CLIENT_ID")
	sandboxesToken := os.Getenv("SANDBOXES_TOKEN")

	// Check required environment variables
	if latticeEndpoint == "" || clientId == "" || clientSecret == "" || sandboxesToken == "" {
		fmt.Println("Missing required environment variables")
		os.Exit(1)
	}

	// Initialize headers for sandbox authorization
	headers := http.Header{}
	headers.Add("Anduril-Sandbox-Authorization", fmt.Sprintf("Bearer %s", sandboxesToken))
	// Create the client
	LatticeClient := client.NewClient(
		option.WithClientCredentials(clientId, clientSecret),
		option.WithBaseURL(fmt.Sprintf("https://%s", latticeEndpoint)),
		option.WithHTTPHeader(headers),
	)

	fmt.Println("Starting task stream...")

	ctx := context.Background()

	// Create task stream request
	request := &Lattice.TaskStreamRequest{
		HeartbeatIntervalMs:     Lattice.Int(10000),
		ExcludePreexistingTasks: Lattice.Bool(false),
		TaskType: &Lattice.TaskStreamRequestTaskType{
			TaskStreamRequestTaskTypeTaskTypePrefix: &Lattice.TaskStreamRequestTaskTypeTaskTypePrefix{
				// Define a prefix filter for tasks that belong to your organization
				TaskTypePrefix: "type.googleapis.com/<your-organization>.tasks",
			},
		},
	}

	// Start the task stream
	stream, err := LatticeClient.Tasks.StreamTasks(ctx, request)
	if err != nil {
		fmt.Printf("Failed to start task stream: %v\n", err)
		return
	}
	defer stream.Close()

	// Process the stream events as they arrive
	for {
		event, err := stream.Recv()
		if err != nil {
			fmt.Printf("Error receiving task stream event: %v\n", err)
			return
		}

		if event.Event == "heartbeat" {
			// Process heartbeat events
			timestamp := *event.GetHeartbeat().GetTimestamp()
			fmt.Printf("Heartbeat: %v\n", timestamp)
		} else {
			task := event.GetTaskEvent().GetTaskEvent().GetTask()
			taskId := task.GetVersion().GetTaskID()
			status := task.GetStatus().GetStatus()

			fmt.Printf("  TaskID: %v\n", *taskId)
			fmt.Printf("  Status: %v\n", *status)
		}
	}
}
```

该流会产生两种主要事件类型：

- heartbeat：常规服务器 heartbeat，用于确认连接处于活跃状态。
- task_event：关于任务创建、更新或状态变化的通知。

## 取消任务

[`CancelTask`](/reference/rest/tasks/cancel-task) API 通过在系统中将任务标记为待取消来取消任务。其行为取决于任务当前状态：

- 如果任务尚未发送给 agent，它会立即取消并转换为终止状态（STATUS_DONE_NOT_OK，并带有 ERROR_CODE_CANCELLED）。
- 如果任务已经发送给 agent，取消请求会路由到该 agent，由它决定接受还是拒绝取消。

本节涵盖取消流程中的操作员侧：发送请求并读取结果。接收被路由请求的 agent 必须设置任务处理器并处理取消请求，请参阅 agent 集成指南中的[处理任务取消](/guides/tasks/integrate-an-agent#handle-task-cancellation)。

1

### 请求取消任务

向 Lattice 发送任务取消请求。如果任务已经发送给 agent，Lattice 会将请求路由给该 agent：

```
package main

import (
	"context"
	"fmt"
	"net/http"
	"os"

	Lattice "github.com/anduril/lattice-sdk-go/v4"
	"github.com/anduril/lattice-sdk-go/v4/client"
	"github.com/anduril/lattice-sdk-go/v4/option"
)

func main() {
	// Get environment variables
	latticeEndpoint := os.Getenv("LATTICE_ENDPOINT")
	clientSecret := os.Getenv("LATTICE_CLIENT_SECRET")
	clientId := os.Getenv("LATTICE_CLIENT_ID")
	sandboxesToken := os.Getenv("SANDBOXES_TOKEN")

	// Check required environment variables
	if latticeEndpoint == "" || clientId == "" || clientSecret == "" || sandboxesToken == "" {
		fmt.Println("Missing required environment variables.")
		os.Exit(1)
	}

	// Check for required command-line arguments
	if len(os.Args) < 2 {
		fmt.Println("Usage: go run cancel_task.go <task_id> [entity_id]")
		os.Exit(1)
	}

	taskId := os.Args[1]
	var entityId *string
	if len(os.Args) > 2 {
		entityId = &os.Args[2]
	}

	// Initialize headers for sandbox authorization
	headers := http.Header{}
	headers.Add("Anduril-Sandbox-Authorization", fmt.Sprintf("Bearer %s", sandboxesToken))

	// Create the client
	LatticeClient := client.NewClient(
		option.WithClientCredentials(clientId, clientSecret),
		option.WithBaseURL(fmt.Sprintf("https://%s", latticeEndpoint)),
		option.WithHTTPHeader(headers),
	)

	// Create context for the request
	ctx := context.Background()

	// Build author based on whether entity_id is provided
	var author *Lattice.Principal
	if entityId != nil {
		author = &Lattice.Principal{
			System: &Lattice.System{
				EntityID: entityId,
			},
		}
		fmt.Printf("Cancelling task: %s\n", taskId)
		fmt.Printf("Author entity: %s\n", *entityId)
	} else {
		userId := "operator_1"
		author = &Lattice.Principal{
			User: &Lattice.User{
				UserID: &userId,
			},
		}
		fmt.Printf("Cancelling task: %s\n", taskId)
	}

	// Create cancel task request
	cancelRequest := Lattice.TaskCancellation{
		TaskID: taskId,
		Author: author,
	}

	// Call the CancelTask API
	_, err := LatticeClient.Tasks.CancelTask(ctx, &cancelRequest)
	if err != nil {
		fmt.Printf("Error cancelling task: %v\n", err)
		os.Exit(1)
	}

	fmt.Printf("Cancel task response: {}\n")
}
```

`CancelTask` API 接受下列参数：

- `taskId` _StringRequired_
  要取消任务的唯一标识符。

- `author` _PrincipalRequired_
  请求取消的是谁或什么。可以是带有 [`userId`](/reference/rest/tasks/cancel-task#request.body.author.user.userId) 的用户 [`Principal`](/reference/rest/tasks/cancel-task#request.body.author)，也可以是带有 [`entityId`](/reference/rest/tasks/cancel-task#request.body.author.system.entityId) 的系统 `Principal`。

使用要取消任务的 ID 运行取消请求：

```
python cancel_task.py <task_id>
```

2

### 验证结果

请求取消后，任务会转换为两种结果之一：

**取消成功：**

当 agent 接受取消时，任务会转换为 `STATUS_DONE_NOT_OK`，并带有 `ERROR_CODE_CANCELLED`：

```
Cancelling task: task-123456
Task has been cancelled.
Task Status: STATUS_DONE_NOT_OK
Error Code: ERROR_CODE_CANCELLED
Error Message: Task cancelled by agent.
```

**取消被拒绝：**

当 agent 拒绝取消时，任务会保留当前状态，但包含带有 `ERROR_CODE_REJECTED` 的 `TaskError`：

```
Cancelling task: task-123456
Task could not be cancelled.
Task Status: STATUS_EXECUTING
Error Code: ERROR_CODE_REJECTED
Error Message: Task is already active, and cannot be cancelled.
```

更多信息请参阅 *Lattice API Reference* 中的 `CancelTask`。
